SKILLS · ROUTING · EVIDENCE GATES · QA

skills_UIUX

A design-engineering system for making AI-assisted UI/UX work more explicit, bounded and repeatable.

01 / PROBLEM

A stronger model does not automatically create a more reliable design process

Website work spans different decision types: project truth, research, audience/journey, information architecture, reference intelligence, visual direction, components, implementation, responsive/accessibility checks and release evidence. Loading everything into one prompt increases context noise and makes it harder to know which claims are actually verified.

Failure modeContext overloadToo much knowledge can reduce decision clarity.
Failure modeWrong skill timingA useful method at the wrong phase becomes noise.
Failure modeFalse QA confidenceBuild success can be mistaken for rendered design quality.
Design goalSmallest useful graphLoad only what the active decision requires.
02 / ARCHITECTURE

Two operating modes share one UI/UX knowledge layer

Mode ASkill Library

The host agent controls the workflow and discovers reusable skills only when the task needs them.

Mode BAgent OS

A Development Manager and flow control the lifecycle; specialists reason inside the active stage.

Context ruleProgressive disclosure

External intelligence and deeper references load only for an active knowledge gap.

Gate ruleEvidence before status

Requirements can be verified, justified N/A, future-phase or blocked — not simply called done.

03 / RELIABILITY DESIGN

Hard truth rules are part of the UX system

V5.4 strengthens rendered visual sanity around contrast, shared surface ownership, CTA states, computed browser styles and focal-media cropping. More importantly, the system distinguishes evidence types instead of allowing one signal to impersonate another.

RuleNo evidence → no validated claimResearch language follows evidence status.
RuleBuild ≠ visual QASource/CI cannot certify rendered craft.
RulePrototype ≠ productionSystem reality is stated explicitly.
RuleFailure becomes learningGeneralizable defects can be promoted into regression rules.
04 / WHY IT BELONGS IN THIS PORTFOLIO

The project shows how I think about design beyond one interface

skills_UIUX is not presented as a replacement for research, designers or human judgment. It is evidence of systems thinking: structuring reusable design knowledge, defining authority and truth boundaries, and making quality checks explicit enough to repeat across projects.

CURRENT BOUNDARY

The repository can route skills and run optional provider-managed stages, but rendered browser QA still requires an actual render/observation adapter. A skill or agent cannot truthfully certify visual quality without seeing the rendered result.
