CREATIVE WORKSPACE · PROJECT HEALTH · NEXT ACTION

StudioOS

A workspace concept exploring one product question: how can a small creative team see what needs attention without losing project context?

01 / SCOPE REALITY

The product vision is larger than the slice that is implemented

StudioOS is a self-initiated SaaS concept. The current implementation is intentionally a first vertical slice centered on the overview dashboard — project health, focus tasks, recent activity, review queue, search, notifications and project creation. Navigation outside that slice provides intentional feedback rather than pretending those destinations are complete.

ImplementedOverview dashboardProject health, focus and activity.
ImplementedCore interactionsSearch, task completion, creation, reviews and notifications.
Not yet builtProject detail depthMilestones, versions, comments and approvals are next-slice work.
Data realityLocal stateNo production backend or adoption metric implied.
02 / DESIGN PROBLEM

“Calm” has to be a behavioral property, not a visual adjective

Creative teams move between high-level project health and very specific next actions. A dense dashboard can make every signal feel urgent; an overly minimal dashboard can remove the context needed to act. The design direction therefore treats calm as prioritization, reversible actions and restrained feedback.

01 / SignalProject health

Surface only the information that changes what the user should notice.

02 / FocusToday’s attention

Connect the strongest signal to an actionable task or review.

03 / ContextKeep project meaning

Task information stays connected to project, priority and due context.

04 / FeedbackQuiet confirmation

Toasts, dialogs and reversible actions confirm changes without spectacle.

03 / INTERFACE PROOF

The first slice is designed as a coherent system, not a dashboard mockup

IMPLEMENTED OVERVIEW SLICE

Persistent orientation

Navigation keeps workspace position visible while the main surface remains focused on work, not chrome.

Operational hierarchy

Health, today’s attention, activity and reviews have different visual weight according to action urgency.

Interaction feedback

Task completion, creation, review dialogs and notifications make the prototype behave like a product slice rather than a static shot.

04 / OUTCOME & BOUNDARY

A reviewable first slice with a clear next product question

The prototype makes the dashboard interaction model tangible before investing in the deeper project data model. The next slice is explicitly defined as project detail with milestones, task filters, deliverable versions, comments and client-safe approval states.

NOT CLAIMED

No team interviews, production persistence, adoption data or delivery metrics are claimed. The information architecture should be validated with real users before the local model expands into a production backend.
