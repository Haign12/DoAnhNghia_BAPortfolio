BANKING · TRUST · TASK-ORIENTED INFORMATION ARCHITECTURE

Vietbank Redesign

An independent banking redesign that treats trust and system reality as interaction requirements, not just visual tone.

01 / CONTEXT

Banking clarity depends on what the interface refuses to imply

The redesign explored a task-oriented Vietbank web experience while preserving a strict boundary between prototype behavior and real banking operations. The repository documents audience intent, website audit, reference benchmarking, design decisions, interaction specifications, system reality, validation planning and QA — making the design process inspectable rather than relying on retrospective storytelling.

02 / DESIGN DECISIONS

Top tasks and safe handoffs shape the information architecture

01 / DiscoverStart from intent

Users can approach cards and banking services through needs rather than product-name knowledge.

02 / CompareOrient, don’t approve

Comparison tools help frame options while clearly handing final terms to official sources.

03 / EstimateSeparate estimate from live data

Utility calculations do not pretend locally entered values are current bank rates.

04 / RecoverSafe support routes

Security, migration and support journeys prioritize verified official channels.

03 / EVIDENCE MODEL

The case separates what was checked from what still needs users

04 / OUTCOME & BOUNDARY

A documented production-candidate concept, not a production bank

The repository’s V7 QA records successful TypeScript, production build and GitHub Pages shell verification, while explicitly keeping responsive visual sign-off, performance evidence, formal accessibility and human usability validation as partial or unverified. That boundary is part of the design quality, not a disclaimer added afterward.

NOT CLAIMED

This is not a production Vietbank website, validated UX, WCAG-conformant system or performance-proven banking product. The current usability plan targets 6–8 moderated sessions and remains pending until real participants complete the defined tasks.

05 / REFLECTION

Trust is strongest when the interface is explicit about its authority

The most transferable lesson was that high-trust domains require a different definition of polish. A beautiful calculator that looks live when it is not is a design failure. The next meaningful step is not more visual refinement; it is moderated task validation and rendered device QA against the documented critical journeys.
