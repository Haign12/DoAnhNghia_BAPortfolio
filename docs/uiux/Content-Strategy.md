# Content Strategy

## Content job

Turn the portfolio from a collection of attractive interfaces into a concise proof system for hiring/project decisions.

## Language

- Required project language: **Vietnamese**.
- Existing primary copy is English: FACT.
- Redesign implementation should use natural professional Vietnamese for primary UI/content while retaining unavoidable product/project names and recognized design terms where clearer.
- SEO metadata/canonical intent should remain aligned with each page rather than literal keyword translation.

## Homepage narrative

### 1. Positioning
Answer immediately:
- who: Đỗ Anh Nghĩa;
- role: UI/UX Designer;
- value: turns complexity into clear product experiences through flows, hierarchy and systems;
- availability/contact signal.

### 2. Selected work
Show a curated proof sequence, not an undifferentiated gallery.

Recommended hierarchy:
1. one flagship project with strongest end-to-end/system proof;
2. two complementary projects that demonstrate range;
3. redesign proof;
4. secondary/archive evidence.

Exact final ranking may change only if new project evidence is stronger.

### 3. Approach/profile
Keep concise. Explain how work is approached after the user has seen proof.

### 4. Experience
Use verified role/company/date facts; avoid inflating responsibility beyond current evidence.

### 5. Contact
Direct, calm, explicit. Email remains the owned action available today.

## Case-study content model

Every primary case study should expose the following fields/chapters, adapted to page role rather than forced into identical blocks:

1. Project type/status.
2. Context/problem.
3. Role/contribution/scope.
4. Constraints/assumptions.
5. User/business question.
6. Key decisions — why this, not only what.
7. Supporting artifacts/screens/system evidence.
8. Implemented output.
9. Outcome/what the design enables.
10. What remains unverified.
11. Reflection/next validation.
12. Next relevant project/contact.

## Evidence writing rules

### Allowed factual language
- “Tôi thiết kế…” when source supports contribution.
- “Giao diện ưu tiên…” for observable design behavior.
- “Concept này khám phá…” for self-initiated work.
- “Bản triển khai hiện tại…” for source-observable implementation.

### Required uncertainty language
- “giả thuyết”; “chưa đo lường”; “cần kiểm chứng”; “bước validation tiếp theo”.

### Prohibited
- invented conversion uplift;
- invented user quotes/test results;
- invented client outcomes;
- fake testimonials/logos/awards;
- “validated”, “improved UX”, “production-ready” without evidence.

## CTA/content relationship

- Home primary narrative CTA: choose a project.
- Case study primary narrative CTA: continue proof / next relevant project.
- Contact is always visible as utility, becomes stronger after evidence.
- Resume is persistent recruiter utility.

## Trust model

Trust comes from:
- specific role/contribution;
- real project links/assets;
- honest limits;
- consistent professional writing;
- verified experience/CV;
- visual craft of the portfolio itself.

## SEO intent preservation

- Preserve current route intent and canonical URLs.
- Keep descriptive project titles and CreativeWork schema strategy.
- Repair sitemap coverage later.
- No route/content retirement without Search Console/backlink evidence.

## Content acceptance

Before code:
- every primary route has a page job;
- every primary case has a proof plan;
- all quantitative claims have source or are removed;
- Vietnamese copy can fit desktop composition without relying on English-short line lengths;
- contact/CV remain obvious but not dominant over work proof.
