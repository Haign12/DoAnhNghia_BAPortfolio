Product practice

Decisions before screens.

Polished UI is only useful when the team can explain what decision it supports, what evidence shaped it, what trade-off was made and how the result will be checked. My work therefore connects product framing, information architecture, interaction states, visual systems, working code and evidence-aware QA.

01

Frame the decision, not the screen

Start with the user decision, owner objective, risk and success signal before choosing a feature or layout.

02

Separate evidence from hypothesis

Benchmarks, AI critique and heuristic review can guide a design; they do not become user research unless users actually produced the evidence.

03

Carry intent into working behavior

Flows, states, responsive rules and recovery paths belong in the prototype — not only in presentation slides.

04

Use AI to increase leverage, not authority

AI can inspect, synthesize, generate alternatives, implement and test. Humans retain product priorities, research interpretation, trade-offs and release judgment.

How I use AI

AI is a multiplier, not the product owner.

My workflow uses AI where it creates leverage — grounding, synthesis, alternatives, implementation, critique and QA — while keeping user evidence, product priorities, design rationale and release decisions explicitly human-owned.

01 / GROUND + SYNTHESIZEVERIFIED

Start from project truth

Agents inspect the repository, brief, routes, constraints and evidence gaps before proposing UI. Facts, inferences, assumptions and unknowns stay separated.

Inspect agent contract ↗
02 / EXPLORE + CRITIQUEVERIFIED

Generate options, then govern them

References and AI alternatives pass through ADOPT / ADAPT / REJECT decisions. Model critique can reveal risks, but it is never relabeled as user research.

Inspect routed skills ↗
03 / DESIGN → CODEVERIFIED

Pair on implementation

AI helps translate approved flows, states, tokens and responsive contracts into working products. Static prototypes stay labeled honestly; Resolve AI is a CI-verified Next.js 16 / React 19 / TypeScript 7 implementation with typed state, App Router and production build/typecheck gates.

Inspect Next/TS proof ↗
04 / VERIFY + REPAIRVERIFIED

Rendered pixels are evidence

Playwright/Chromium, axe-core and Lighthouse diagnostics check routes, viewports, accessibility and visual integrity. Failures loop back to the stage that owns the problem.

Inspect cloud QA ↗
